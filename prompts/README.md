# Prompts

Run these from the **task repo root** (where `PROJECT.md` lives). Each file is a standalone prompt:
one-line purpose, when to run it, the copy-pasteable body, and what you should get back.

## Placeholder convention

- Exactly one form: `<PROJECT_REPO>` style — uppercase with underscores inside angle brackets (e.g. `<TASK_REPO>`, `<TRACK>`).
- Every placeholder that appears in a prompt is listed in `SETUP.md` with an example value.
- Fill `PROJECT.md` first; after that no placeholder should remain in a command you run.
- Prompts are generic for all tracks; they read `CORE_STANDARDS.md` and `GOLD_STANDARD.md`
  for track-specific bars.

## Order

Prompts are numbered `01` to `09` in the order you typically run them: ideate (01–05),
evaluate (06), scaffold (07), calibrate (08), and review loop (09). You may skip or
reorder ideation prompts (01–05) — they are alternative entry points to the same board.
Do not skip the human gates (06 vs 08 are assists, not approvals).

## Human gates

No prompt writes `instruction.md` or authors test assertions. Prompts may gather,
propose, scaffold, prove, and calibrate. They stop at the gate and leave a draft
note for the human to rewrite (see `07-scaffold-and-prove.md`).
